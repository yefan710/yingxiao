# User Pain Points

Source: `/Users/admin/稿定/稿定/Clippings/JD-AI商品素材微应用- V1.0 - 欢乐逛：tiger - 稿定星球 1.md`

## Target Users

- 京东/京麦商家运营：负责商品图、详情图、搜索推荐图、卖点图等素材生产和上架。
- 多 SKU 店铺运营：需要批量处理大量商品素材，且要保证不同坑位素材规格正确。
- 非设计专业商家：没有稳定设计师或拍摄修图资源，但需要专业级商品视觉内容。

## Core Pain Points From PRD

1. 素材制作成本高：专业拍摄、修图、人力和物料投入大。
2. 制作周期长：从物料准备、拍摄、修图到上传商品链路长，促销节点响应慢。
3. 多场景覆盖难：商品需要透图、白底图、场景图、搜索推荐图、卖点图等多类素材。
4. 批量运营压力大：海量 SKU 需要规模化生成、确认、重试和发布。
5. 商品发布链路容易断：素材生成后还要回填到商品坑位，单张、多张、SPU/SKU 维度容易选错。
6. 效果确认成本高：生成后需要查看大图、确认效果、失败重试、跳过不替换。
7. 权益和点数认知复杂：免费点数、付费点数、套餐外内购、单张扣点需要被用户理解。

## Value Claims With Source Status

- 降低素材制作成本 90% 以上：PRD 已写，详情页使用时标 `NEEDS_SOURCE_FOR_PUBLIC_CLAIM`，需要确认是否可公开。
- 效率提升 100 倍以上：PRD 已写，详情页使用时标 `NEEDS_SOURCE_FOR_PUBLIC_CLAIM`。
- 30 秒生成素材：PRD 已写，详情页使用时标 `NEEDS_SOURCE_FOR_PUBLIC_CLAIM`。
- 批量生成支撑海量 SKU：PRD 已写，可作为功能能力表达，但不要写具体 SKU 数量。

## Safer Public Copy Direction

- 少用未经证明的极限数据，多用可由功能截图支撑的能力文案。
- 推荐表达：
  - "对话生成商品素材"
  - "批量生成多类商品图"
  - "生成后确认再发布"
  - "成功、失败、执行中分状态管理"
  - "支持发布至商品坑位"
- 谨慎表达：
  - "成本降低90%以上"
  - "效率提升100倍以上"
  - "30秒生成"
