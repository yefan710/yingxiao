# 07 QA Scorecard

## Scorecard

| Dimension | Weight | PASS Standard | Blocking Examples |
| --- | --- | --- | --- |
| Requirement fit | 15 | 页面能让目标用户快速理解产品价值，且不出现已确认不支持能力 | 目标用户错 / 核心卖点缺失 / 页面模式判断错 / 写了回填商品或发布回商品 |
| Information structure | 15 | 正确识别 part1 头图、part2 功能汇总图、part3 各功能配图；每张图只讲一个主要任务 | 头图识别错 / 缺少功能汇总图 / 功能配图和汇总功能不一致 / 把 part2 当普通功能配图 |
| Copy fit | 15 | 标题、副标题、模块文案符合字数预算、字号层级和来源依据；功能配图使用短标题 + 2-3 条能力证明；中文标点和分隔符排版自然 | 标题溢出 / 字号层级混乱 / 长段落无法落版 / 虚假承诺 / 无来源数据 / 文字遮挡 / 随机中文 / 标点居中异常 |
| Visual consistency | 15 | 色彩、字体、组件、截图处理符合对应规范：part1/part2 使用功能汇总头图色板，part3 使用功能说明色板，旧版 1500 x 1125 使用功能配图色板 | 风格明显跑偏 / 像另一套品牌 / 脱离对应 part 指定色板 / 高饱和色块突兀 / 装饰图形抢主体 / 像脚本硬画工程稿 |
| Image2 production discipline | 10 | image2 生成完整视觉和中文文案排版；本地合成阶段只贴入真实截图，不重排文案或硬画卡片 | image2 只做背景 / 脚本重排标题、bullet、卡片 / 截图槽之外出现脚本补视觉 / 文案和视觉不是同一生成体系 |
| Part3 image type | 10 | part3 正确区分功能配图和功能说明/2图混合层：功能配图为文案+配图，功能说明为文案+配图+框 | 功能配图错误套大框 / 功能说明缺少框 / 多图混合没有承载层 / 单界面工具被做成复杂混合层 |
| Asset proof | 10 | 关键卖点有真实截图、真实设计稿、图示或证明支撑；后台 UI 必须通过 mask 坐标贴入真实截图，不能由 AI 重绘；截图区域不能遮挡文案 | 重要卖点只有抽象文字 / 缺少真实截图 / AI 重绘后台界面 / 截图被拉伸变形 / 截图包含未脱敏敏感信息 / 截图遮挡标题、bullet、底部标注 |
| Conversion clarity | 5 | 首屏价值清楚，后续屏能回答购买疑虑 | 首屏不知道卖什么 / CTA 或服务承诺缺失 |
| Production spec | 5 | 尺寸、命名、导出、源文件符合要求 | 尺寸错误 / 缺源文件 / 图片不可读 |

## Release Rule

- 90-100: PASS
- 80-89: PASS WITH POLISH
- 70-79: FIX IMPORTANT ISSUES
- Below 70: FIX REQUIRED
- Any blocking issue: FIX REQUIRED

## Codex Prompt

# 质检员

你是详情页质检员。请基于最终视觉稿、已确认需求包、屏幕规划、文案和视觉规范，做发布前质检。

## 要求

1. 按屏幕逐项检查，不要只给总体评价。
2. 每个问题标 severity：`blocking` / `important` / `polish`。
3. 每个问题必须给出明确修改指令。
4. 有 blocking 问题时，结论必须是 `FIX REQUIRED`。
5. 先做 part 身份识别：part1 是头图，part2 是功能汇总头图，part3 才是功能配图/功能说明。识别错直接 blocking。
6. 检查详情页结构是否完整：part1 头图、part2 功能汇总图、part3 各个功能配图。
7. 检查 image2 分工是否正确：文案排版、功能卡片、标题层级必须由 image2 生成；本地合成只能贴真实截图。若脚本硬画或重排大段文案，直接 blocking。
8. 检查色值是否遵守对应 part 规范：part1/part2 用功能汇总头图色板，part3 用功能说明色板，旧版 1500 x 1125 功能配图用 `#c1d5ed`、`#8f9498`、`#fbfbfb`、`#e5e8fe`、`#bee2d6`。
9. 检查高饱和色块、右上角装饰、强橙/强绿是否突兀；如果明显偏离参考图，标 important 或 blocking。
10. 检查 part3 版型是否正确：功能配图不能错误套大框；功能说明/2图混合层必须有框承载多图。
11. 检查每张图的字数是否符合 `00_design_spec.md`：头图主标题 4-8 字优先，功能配图标题 4-7 字优先，功能说明标题 4-8 字优先；超出上限就是 important 或 blocking。
12. 检查文字大小和层级：大标题必须最强，bullet 必须可读，截图标注不能比主标题抢层级，真实截图文字要能辨认。
13. 检查文案风格：必须是短功能名 + 能力/范围/操作结果，不能出现空泛口号、无来源效果承诺、长段落。
14. 检查中文标点：避免使用会产生居中异常的 `、`、`，`；优先使用空格、`｜`、` / ` 等分隔方式。发现标点视觉异常，至少 important。
15. 检查所有文字和截图是否互不遮挡；功能配图中任何截图压住标题、bullet、底部标注都直接 blocking。
16. 检查后台 UI 和功能截图是否为真实截图/设计稿贴入；如果看起来是 AI 重绘、虚构数据或假界面，直接 blocking。
17. 检查 mask 坐标和最终贴图是否一致：截图没有拉伸变形、没有糊、没有被遮挡，圆角/阴影/描边符合规范。
18. 检查截图是否完成必要脱敏：店铺名、手机号、订单号、客户信息、金额等敏感内容不能直接发布。
19. 检查不支持能力：不得出现回填商品、发布回商品、发布到店铺等用户已确认不支持内容。
